# SUNSCRYPT — правила проекта

Сервис автоматической торговли перпетуалами на Bybit: сигнал Kronos →
исполнение NautilusTrader → Bybit, дашборд в реальном времени, Telegram-бот.
Полный контекст — `docs/BRIEF.md`: прочитать целиком перед работой.

Владельцу — по-русски, простыми словами, без воды и без технического жаргона
там, где можно без него. Работать самому; спрашивать только то, без чего
нельзя.

## Где код и как он выкатывается

Решение владельца, 06.10.2026: «Делаем через новую сессию, создай ветку в гит
и авто деплой. Размещаем у нас на сервере, не спрашивай разрешений, делай».
Позже в тот же день владелец завёл отдельный репозиторий и велел перенести
проект туда.

- **Репозиторий `egeg23/SUNSCRYPT`, ветка `main`** — здесь весь код. Ветка
  `sunscrypt` в `egeg23/DevUZ-perfect-` заморожена (история перенесена сюда).
- **Каждый пуш в `main` выкатывается сам** (после линтеров, тестов и
  сквозного теста в браузере): `.github/workflows/sunscrypt-deploy.yml` → SSH
  на наш сервер → `/opt/sunscrypt` → `infra/deploy.sh` → Docker Compose, проект
  `sunscrypt`. Итог и адрес — в последней строке лога выкатки («Готово:
  https://…»).
- **Адрес временный**: `sunscrypt.<ip-сервера>.sslip.io` (`PUBLIC_HOST` в
  `.env` на сервере). Переезд на maximov-tech.ru — сменой `PUBLIC_HOST`.
- Секреты сервера (VPS_*, SUNSCRYPT_*) пока лежат в `egeg23/DevUZ-perfect-`
  (GitHub не даёт их перенести). Поэтому после зелёных проверок здесь выкатку
  запускает workflow `sunscrypt-deploy.yml` ветки `sunscrypt` того репозитория
  (workflow_dispatch, ref `sunscrypt`); он берёт свежий `main` отсюда.
  Секреты появятся здесь — выкатка пойдёт отсюда сама.
- Проверять, что выкатка доехала, — после каждого пуша: лог задачи в Actions
  и ответ сайта.
- Доступ к сервису закрытый: регистрации нет, только приглашения владельца
  (`/admin`). Владелец создаётся из секретов `SUNSCRYPT_OWNER_*`.

## Сервер общий — трогать только своё

На том же сервере работают devuz.studio, витрина globalex и другие проекты.

- Только свой проект Compose (`-p sunscrypt`), свой порт (`WEB_PORT`, диапазон
  3470–3499) и свой сайт nginx (`/etc/nginx/sites-available/sunscrypt`).
- Никаких `docker system prune`, `docker compose down` без `-p sunscrypt`,
  правок чужих конфигов nginx, перезапусков чужих служб.
- `nginx -t` перед каждой перезагрузкой; не прошёл — откат (так делает
  `infra/deploy.sh`).
- У каждого контейнера — `mem_limit`: сервер не должен уйти в своп из-за
  SUNSCRYPT. Сколько у сервера CPU и памяти — выяснить первым делом (шаг в
  выкатке) и уложиться.
- Сервер стоит в России. Доступ к api.bybit.com, api-demo.bybit.com и
  stream.bybit.com проверить с сервера (шаг в выкатке) до того, как строить на
  нём исполнение. Не пускает — сказать владельцу и предложить выход.

## Секреты

Репозиторий **публичный**. В git, логах, чате и ответах интерфейса — ни
одного секрета.

- Секреты сервера — `/opt/sunscrypt/.env` (только root). Первая выкатка сама
  создаёт `POSTGRES_PASSWORD`, `MASTER_KEY` (AES-GCM для ключей
  пользователей), `SESSION_SECRET`; выкатка их не перезаписывает.
- Секреты, которые даёт владелец (токен Telegram-бота, демо-ключи Bybit для
  проверки), в чат не просить. Путь — секрет репозитория GitHub с префиксом
  `SUNSCRYPT_` (владелец заводит его в Settings → Secrets → Actions), выкатка
  дописывает его в `.env` на сервере. Механизм сделать, когда понадобится
  первый такой секрет, и написать владельцу, какой секрет завести.
- Ключи Bybit пользователей — только шифрованно в БД (мастер-ключ из `.env`),
  в интерфейс не возвращаются.

## Жёсткие правила из брифа (не нарушать)

1. Реальные ордера — только после явного решения владельца. По умолчанию всё
   в демо; mainnet заблокирован флагом и подтверждением.
2. Ключи Bybit с правом вывода или переводов — отклонять. Требовать привязку
   к IP сервера.
3. Плечо ≤ 2×, по умолчанию 1×. Дневной лимит убытка, аварийная остановка —
   общая и на кабинет.
4. В репозиторий модели Kronos (`shiyu-coder/Kronos`) не пушить.
5. Никаких обещаний прибыли. Честная статистика после комиссий и
   предупреждение о рисках — на видном месте.
6. Стратегия идёт в торговлю только после проверки на данных, которых она не
   видела, после комиссий.
7. Если пользователи — не только владелец и команда: предупредить владельца о
   юридической стороне и рекомендовать юриста до приёма реальных денег.

## Ответы владельца на вопросы брифа (раздел 6)

1. **Сервер** — наш, тот же, где devuz.studio. IP и ресурсы — из лога
   выкатки.
2. **Репозиторий** — `egeg23/SUNSCRYPT`, ветка `main` (публичный).
3. **Пользователи** — закрытое использование: владелец и команда, доступ —
   только по приглашениям владельца; реальный режим выключен у всех.
4. **Telegram** — бот @SUNSCRYPT_tradebot создан; подключение отложено
   владельцем («пропускаем, обкатываем»). Токен — секретом
   `SUNSCRYPT_TELEGRAM_TOKEN`, когда дойдём (старый был в чате — нужен новый).
5. **Демо-ключи Bybit** — секретами `SUNSCRYPT_BYBIT_DEMO_API_KEY` и
   `SUNSCRYPT_BYBIT_DEMO_API_SECRET`, не в чат.

## Код прошлой сессии (исследование Kronos)

Перенесён в `engine/` (из `kronos-bybit`). Веса дообученной модели в git не
лежат: выкатка скачивает их с Google Диска владельца по ID из секрета
`SUNSCRYPT_WEIGHTS_IDS`, сверяет sha256 (`infra/model-weights.txt`) и кладёт в
`/opt/sunscrypt/models`.
