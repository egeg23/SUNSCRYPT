## 1. Что строим

**SUNSCRYPT** — веб-сервис автоматической торговли криптовалютными перпетуалами на Bybit.

Пользовательский путь:
1. Регистрация → вход (с 2FA).
2. Дашборд → «Добавить кабинет»: пошаговая инструкция, как создать API-ключ Bybit, ввод ключа, автоматическая проверка ключа.
3. Переключатель **Демо ↔ Реальный счёт** (демо — по умолчанию).
4. Дашборд в реальном времени: **график роста от начального баланса**, **успешность сделок в %**, сделки, позиции, просадка, комиссии и фандинг.
5. Telegram-бот: уведомления о сделках, дневной отчёт, тревоги, аварийная остановка.

Внутри: сигнал модели **Kronos** (дообученная small) → исполнение через **NautilusTrader 2.x** → Bybit.
«Самообучение» — в контролируемой форме (см. раздел 5, этап 8).

- Название: **SUNSCRYPT**. Логотип, палитра, Telegram-бот (имя, описание, аватар) — делаешь ты.
- Домен в будущем: **maximov-tech.ru**. Сейчас — **не на поддомене**: временный хост, потом перенос на домен.
- Пары: от 1 до 10, с лучшими **подтверждёнными** результатами (процедура отбора — этап 7).

### 2.1 Ключевые выводы (честно, цифрами)

Тест без подглядывания: июль 2025 – сентябрь 2026, 6 пар (BTC, ETH, SOL, XRP, BNB, ADA), комиссии Bybit VIP0
(тейкер 0.055% + 0.02% проскальзывания на сторону, мейкер 0.02%), фандинг учтён, плечо 1×.

- **Kronos «из коробки» (mini/small/base) на крипте не предсказывает направление:** 47–51% угаданных, хуже прогноза «цена не изменится», систематически ставит против недавнего движения. Base (102M) не лучше small.
- **Kronos-large (499M) не опубликована** (README ❌, на HF нет; issues #6, #352). Есть только mini/small/base.
- **Данные предобучения Kronos заканчиваются июнем 2024** — честный тест только после этой даты.
- **Дообучение small на свечах Bybit — главный выигрыш:** IC 1h −0.035 → +0.041; сырой сигнал Sharpe (тейкер) −2.52 → −0.79.
- **Лучшая заранее выбранная стратегия** (дообученная small, вычитание сдвига прогноза, торговать при |z|>1):
  - 1h: тейкер Sharpe 0.01 (−2.6%), мейкер Sharpe 1.15 (+32.7% при условии полного исполнения лимиток);
  - 4h: тейкер 0.02 (−2.4%), мейкер 0.39 (+8.1%).
  - Комиссии съедают 92–98% валового результата. Мейкерский плюс статистически не отличим от удачи (t≈1.3).
- **В движке Nautilus** (реалистичнее по исполнению лимиток; без фандинга):
  | Стратегия | 4h тейкер | 4h мейкер | 1h тейкер | 1h мейкер |
  |---|---|---|---|---|
  | Kronos дообученный, |z|>1 | −1.1% | +3.6% | +0.7% | **+12.5%** |
  | Моментум без модели | **+53%** | **+48%** | −95%* | −30% |

  \*фиксированный размер позиции в движке раздувает убыток; в исследовании было −67%.
  Моментум на 4h был в плюсе и на валидации, и на тесте.
- **«Самообучение» проверено на истории:**
  - ежемесячное переобучение Kronos: 1h ухудшилось (тейкер −0.59, −17.9%), 4h чуть лучше (0.19, +2.4%) в пределах шума; IC упал на обоих;
  - мета-фильтр, обучающийся на исходах своих сделок (логистика/LightGBM, статично и с ежемесячным дообучением): на 1h всегда хуже, на 4h не лучше «торговать каждый сигнал».
  - **Вывод:** работает только контролируемое переобучение с проверкой «чемпион/претендент» и откатом.
- **Чужие крипто-дообучения Kronos на HF** (lc2004 BTC 1h/4h, faizack BTC 1h) не лучше исходных моделей.
- **По парам (1h, тест, тейкер, только для ориентира — выбирать по этому нельзя, это подгонка):** BTC +21%, XRP +17%, ADA +10%, SOL −17%, BNB −19%, ETH −41%.

**Главный рычаг прибыли — исполнение (лимитные/мейкерские ордера) и выбор стратегии, а не размер модели.**
Сервис обязан показывать пользователю честные цифры. **Прибыль не гарантирована.**

### 2.2 Находки в коде Kronos (учесть при использовании)
- Нет KV-кэша → медленно. Наш `src/fastkronos.py` даёт ×36–51 на CPU, выход идентичен оригиналу.
- Сэмплы усредняются внутри → разброс теряется. Наша версия отдаёт все сэмплы.
- Скрипты дообучения без teacher forcing; `finetune_csv` нормализует по окну с будущим. Наш `src/finetune.py` исправлен.
- RoPE в слое s2 на инференсе с позицией 0 — дефект, на метрики почти не влияет.
- Веса — safetensors, `trust_remote_code` нет.

## 3. Жёсткие правила (не нарушать)

1. **Реальные ордера** — только после явного решения владельца. По умолчанию всё в демо. Mainnet-режим заблокирован флагом/подтверждением.
2. **Секреты** (API-ключи пользователей, токены) — никогда в коде, логах, чате, репозитории. Ключи пользователей — только шифрованно в БД (AES-GCM, мастер-ключ в секретах сервера). В интерфейс не возвращать.
3. **Ключи Bybit с правом вывода/переводов — отклонять.** Требовать привязку к IP сервера.
4. **Плечо ≤ 2×**, по умолчанию 1×. Дневной лимит убытка, аварийная остановка (глобальная и на кабинет).
5. В репозиторий Kronos не пушить. Код SUNSCRYPT — в отдельном репозитории (уточнить у владельца).
6. Никаких обещаний прибыли в интерфейсе и текстах. Показывать честную статистику и предупреждение о рисках.
7. Модель/стратегия выходит в торговлю только после проверки на данных, которых она не видела, **после комиссий**.
8. Если пользователи сервиса — не только владелец: обязательно предупредить о юридической стороне (РФ: регулирование цифровых валют и доверительного управления) и рекомендовать юриста до приёма реальных денег.

## 4. Технические факты (проверено)

- **Bybit API из облачных контейнеров Claude закрыт гео-блоком** (CloudFront 403 для api.bybit.com, testnet, demo). Работает архив `https://public.bybit.com` (свечи `kline_for_metatrader4/` до ноября 2024, **время в UTC+3** — вычитать 3 ч; сделки `trading/` по дням). Для свежих данных — `https://data.binance.vision` (UM-перпетуалы и фандинг), цены совпадают с Bybit (корреляция доходностей 1.00).
- Живой Bybit проверять **только на сервере владельца** (не США/Китай).
- **У Bybit нет вебхуков.** Реальное время — приватный WebSocket: позиции, исполнения, ордера, кошелёк.
- **Bybit Demo Trading:** REST `https://api-demo.bybit.com`, приватный WS `wss://stream-demo.bybit.com`, публичные данные — mainnet `wss://stream.bybit.com`. WS Trade API на демо нет (Nautilus сам уходит на REST). Пополнение демо: `POST /v5/account/demo-apply-money`. Ключи: bybit.com → Demo Trading → аватар → API.
- **NautilusTrader:** две линии — 1.231.0 (стабильная, август 2026) и 2.0 (кандидаты, rc6 от 5.10.2026, сотни ломающих изменений на релиз; ночные сборки ежедневно на `https://packages.nautechsystems.io/simple`). GitHub-теги и PyPI выходят одновременно. Закреплено `nautilus_trader==2.0.0rc6` в `requirements-nautilus.txt`; обновлять только после `python tools/check_nautilus.py --test` = PASS. Bybit-адаптер: `BybitEnvironment.DEMO/TESTNET/MAINNET`, env-переменные `BYBIT_DEMO_API_KEY/SECRET`, `BYBIT_TESTNET_API_KEY/SECRET`, `BYBIT_API_KEY/SECRET`.
- Kronos-small на CPU: ~0.15 с на прогноз (16 сэмплов × 8 свечей) с нашим ускорением. GPU для бота не нужен.
- Python 3.13, torch CPU (`pip install --index-url https://download.pytorch.org/whl/cpu torch`).

## 5. Пошаговый план (придерживаться; каждый этап закрывать проверкой «Готово, когда»)

### Этап 0. Основа
- Монорепозиторий: `backend/` (FastAPI, Python 3.13), `web/` (Next.js + React + TypeScript), `engine/` (Kronos + Nautilus — перенести из `kronos-bybit/`: `src/fastkronos.py`, `src/finetune.py`, `nt/*`, `tools/check_nautilus.py`), `infra/` (Docker Compose, Caddy с HTTPS).
- PostgreSQL, Redis. Миграции (Alembic). CI: линтеры, тесты, сборка образов.
- Временный хост (не поддомен). Перенос на maximov-tech.ru — сменой DNS и конфига Caddy.
- **Готово, когда:** `docker compose up` поднимает сервис, CI зелёный.

### Этап 1. Бренд
- Логотип SUNSCRYPT (SVG: знак + надпись, светлая/тёмная версии), палитра, шрифты (с кириллицей), favicon.
- Telegram-бот: имя, @handle-варианты, описание, приветствие, аватар 640×640.
- **Готово, когда:** страница бренда согласована с владельцем.

### Этап 2. Регистрация и вход
- Email + пароль (argon2), подтверждение почты, сброс пароля, обязательная 2FA (TOTP) перед добавлением ключей, httpOnly-сессии, rate limit, журнал входов.
- **Готово, когда:** e2e-тесты проходят полный цикл.

### Этап 3. Подключение кабинета Bybit
- Мастер с пошаговой инструкцией (демо и реальный ключ отдельно; права: только Contracts — Orders, Positions; без вывода; привязка к IP сервера).
- Проверка ключа через Bybit API перед сохранением (права, отсутствие вывода, IP-привязка, тип счёта UNIFIED). Отклонять ключ с выводом.
- Шифрованное хранение, ротация мастер-ключа, удаление кабинета.
- **Готово, когда:** демо-ключ проходит; ключ с выводом отклоняется; ключ нигде не виден в логах.

### Этап 4. Торговый движок
- **Сервис сигналов (глобальный):** на закрытии свечи считает прогноз Kronos по каждой паре один раз для всех, публикует в Redis.
- **Исполнение:** на каждый кабинет — процесс NautilusTrader `LiveNode` с `KronosStrategy` (подписка на сигналы вместо локального инференса), лимиты риска, аварийная остановка.
- **Оркестратор:** запуск/остановка/перезапуск процессов, health-check, сверка позиций (reconciliation).
- **Готово, когда:** 3 дня на демо без ручного вмешательства, журнал сделок сходится с Bybit.

### Этап 5. Демо ↔ реальный счёт
- Переключатель в кабинете; демо по умолчанию.
- Включение реального: повторная 2FA, подтверждение рисков, лимит депозита и дневного убытка; глобальный выключатель реальной торговли у админа (по умолчанию выключен).
- **Готово, когда:** переключение не создаёт двойных позиций.

### Этап 6. Дашборд в реальном времени
- Bybit приватный WS (positions, executions, orders, wallet) → backend → браузер (WebSocket/SSE).
- График роста от начального баланса (снимки equity каждую минуту + на каждую сделку), успешность сделок %, число сделок, средний результат, максимальная просадка, комиссии и фандинг отдельно, открытые позиции, лента сделок.
- Графики: TradingView lightweight-charts или ECharts. Тёмная и светлая темы, мобильная версия.
- **Готово, когда:** сделка на демо появляется на графике < 2 с.

### Этап 7. Выбор пар (1–10)
- Вселенная: ~30 самых ликвидных USDT-перпетуалов Bybit.
- Данные: Bybit-архив + Binance UM (см. раздел 4). Разбиение: обучение до 2024-06, валидация 2024-07…2025-06, тест 2025-07…последний месяц.
- Стратегии-кандидаты: Kronos дообученный (1h, мейкер), моментум (4h). Отбор пар и правил **только по валидации**, подтверждение на тесте после комиссий. Не подтвердилось — не берём, даже если пар меньше 10.
- **Готово, когда:** таблица отбора в отчёте, список пар — в конфиге с версией.

### Этап 8. Самообучение (контролируемое)
- Еженедельно: переобучение на свежих свечах → претендент. Реестр версий модели.
- Сравнение «чемпион/претендент» на последних 4 неделях (не виденных претендентом) после комиссий + сравнение с простыми базами. Выпуск только при выигрыше; иначе остаётся чемпион.
- Мониторинг дрейфа: живые результаты против ожидания из бэктеста; при отклонении сверх порога — автоматический откат/пауза.
- **Готово, когда:** в админке история версий и причина каждого выпуска/отказа.

### Этап 9. Telegram
- Привязка через `/start <код>`; уведомления о сделках, дневной отчёт, тревоги (лимит убытка, разрыв WS, ошибка ключа); `/status`, `/stop`.
- **Готово, когда:** уведомление о сделке < 5 с.

### Этап 10. Безопасность и запуск
- Security review, бэкапы БД, мониторинг, логи без секретов, ежедневный `check_nautilus.py --test` по cron.
- Пользовательское соглашение, предупреждение о рисках.
- Запуск: только демо 4–6 недель → закрытая бета на реальных деньгах с малыми лимитами (решение владельца) → перенос на maximov-tech.ru.
